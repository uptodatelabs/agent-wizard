## 실행 원칙

1. 각 과업은 **구현 → 테스트 → 수정 → 커밋/푸시** 순으로 완결한다.
2. 커밋 메시지는 무엇을·왜 바꿨는지 상세히 작성한다.
3. 각 과업 종료 시 `npm run test:run`, `npm run typecheck`, `npm run build`를 재실행하여 회귀를 방지한다.
4. 모든 과업 완료 후 전체 재검증을 거쳐 완성 판정을 내린다.

## 아키텍처 방향

### T2 — 데이터 안전

현재 `sync.ts`와 각 어댑터가 사용자 설정 파일을 **새 객체로 통째로 덮어쓴다**(기존 API 키·hooks·channels 소실).

- `src/core/config-store.ts` 신설
  - `readJson/readYaml` — 기존 원본 로드
  - `mergeDeep(target, source)` — AgentWizard가 관리하는 키만 덮어쓰고, 미관리 키는 보존
  - `backupFile(file)` — 쓰기 전 `<file>.agent-wizard.bak` 타임스탬프 백업
  - `writeJson/writeYaml(file, data, { backup, dryRun })` — dryRun 시 미기입
- 각 어댑터의 `write()`를 **read → merge → write** 방식으로 변경. 미관리 필드는 보존.
- `ProfileSync`는 자체 설정 생성 로직을 제거하고 **어댑터의 write에 위임** (이원화 제거).
- CLI `sync to-tools`에 `--dry-run` 추가 → 미리보기 출력.

### T3 — 진짜 검증

- `src/adapters/<tool>.schema.ts` — zod 스키마 (필수 필드·타입·허용값)
- 어댑터 `validate()`가 **파싱 + 스키마 검증**을 수행, 구체적 오류 메시지 반환.

### T4 — 진짜 상태

- 상태 의미 재정의:
  - `active` — 툴 바이너리 설치 + 유효한 설정 존재
  - `configured` — 유효한 설정 존재 (바이너리 미확인)
  - `error` — 설정 존재하나 스키마 위반
  - `not-configured` — 설정 없음
- 바이너리 존재는 PATH 스캔으로 판정 (OS 크로스플랫폼).

### T5 — 공개 API

- 스텁 `AgentWizard` 클래스를 실제 파사드로 구현:
  - `detect()`, `validate()`, `getStatus()`, `listProfiles()`, `createProfile()`, `syncToTools(config, opts)`
- CLI와 내부 모듈이 동일한 파사드를 사용하도록 정리.

### T6 — CLI 하드닝

- 미지원 툴 입력 시 명시적 오류 (silent success 제거)
- 프로파일 이름 sanitize (경로 주입 방어)
- 명령별 exit code 규칙
- 버전을 package.json에서 읽도록 통일

### T8 — CI·린트·패키징

- `.github/workflows/ci.yml` — install → lint → typecheck → test → build
- eslint flat config 신설, `npm run lint` 통과
- `@types/react`를 devDependencies로 이동, 의존성 정리
- `prepublishOnly`에 test/typecheck 포함
